# Operator Guide: Reading and Using the Calls

This guide explains what a **call** is, how to read one, how to size a trade
from it, and — most importantly — what the system can and cannot promise.
Read the "Honest limits" section before risking any money.

---

## 1. What a call is

A call is the system's current trade plan for one symbol (R_75 = Volatility
75, R_100 = Volatility 100).  It is generated live from real market data
every time you press **Refresh** on the dashboard (or run
`python -m synthetic_trader.cli live-snapshot`).  Every call carries:

| Field | Meaning |
|---|---|
| `call` | `buy_candidate` / `sell_candidate` / `stand_aside` / `no_trade` |
| `entry` / `entry_area` | the price zone where the plan is valid |
| `stop_loss` | where the idea is wrong (risk) |
| `take_profit` (primary target) | the first profit objective (reward) |
| `reward_risk` | reward ÷ risk.  ≥ 2 is a good plan geometry |
| `confidence` | raw model confidence (0–1) — **NOT a probability of winning** |
| `regime` | `volatile` / `normal` / `quiet` (volatility state) |
| `direction_bias` | the multi-timeframe alignment direction |
| `hold_horizon_minutes` | how long the plan is valid (360 = 6 hours) |
| `horizon_verdict` | `calibrated` / `needs_more_data_or_tuning` (vol-band honesty) |
| `evidence_status` | `proven` / `still_learning` / `suppressed` / `unverified` |
| `target_hit_rate` + `sample_size` | empirical win rate for this trigger type, with the evidence count |
| `guardian_state` | the signal-guardian's verdict on the setup |

## 2. Reading a real call (example)

```
R_75 · SELL CANDIDATE · valid · guardian: confirmed
  Entry    7752.48   (area "around 7752.48")
  Stop     7829.55   (risk ≈ 77 points)
  Target   7482.72   (reward ≈ 270 points)   →  R:R 3.5
  Horizon  360 min   ·  verdict: calibrated  ·  bands ×1.54 / ×2.50
  Evidence still_learning (target_hit 4/10)  ·  mode: suppress
```

How to read it top to bottom:

1. **Direction** — `sell_candidate` means the plan is short.  The `why`
   field lists the evidence: "4H bias bearish; 1H trend_down; 15m
   confirmation trend_down; 5m execution trend_down; confluence 0.90".
2. **Risk first** — the stop is the number that matters.  If price reaches
   it, you are out.  Never widen a stop because the target is far away.
3. **R:R = 3.5** — with this geometry you only need to win ~22% of the time
   to break even.  That is why the plan can be profitable even when raw
   confidence is 0.5.
4. **Horizon** — the plan is valid for up to 6 hours.  If it has not
   triggered (or hit stop/target) by then, the call is stale — refresh.

## 3. The empirical gate (what to trust)

Because synthetic-index price is generated by a CSPRNG, **direction has no
true edge** — the model's raw confidence is ~0.5, and Hurst/entropy tests
confirm it.  The system's real edge (such as it is) is in *volatility
timing* and *plan geometry*.  So the system grades its own calls:

- **`proven`** — this (symbol, trigger type) has enough scored outcomes
  (`>= MIN_STAGE3_SAMPLES`, default 10) AND its market-verified target-hit
  rate clears the floor (50% default).  These are the calls worth full size.
- **`still_learning`** — fewer than 10 scored outcomes, or the hit rate is
  below the floor but the sample is too small to be conclusive.  Trade
  smaller or wait.
- **`suppressed`** — enough outcomes and the hit rate is genuinely below the
  floor: the system has stopped emitting this call type (downgraded to
  `stand_aside`) because the market proved it does not work.
- **`unverified` / PAPER ONLY** — no scored outcomes yet at all.  The
  dashboard shows **PAPER ONLY** and execution is blocked until an empirical
  verdict exists.

**Rule of thumb: only `proven` calls get full risk.  Everything else is
smaller, or paper only.**  The dashboard shows the live sample size next to
each call so you can tell "proven" from "still learning" at a glance.

## 4. Sizing a trade (the calculator on the dashboard)

1. Decide your **risk per trade** — for a $5,000 account at 1.5% that is
   **$75**.
2. Read the stop distance from the call (e.g. 77 points on R_75).
3. Lot size = risk_amount ÷ stop_distance, converted to lots for the
   instrument.  The dashboard's **LOT SIZE CALCULATOR** does this for you —
   enter equity, risk %, entry and stop, and it outputs the lot size.
4. **Scale by evidence:** full size only on `proven` calls.  For
   `still_learning`, take a fraction (e.g. 25–50%); for anything
   `unverified`/PAPER ONLY, do not put real money on it at all — run it in
   paper mode first.

## 5. The workflow

1. Open the dashboard, pick V75 or V100, press **Refresh**.
2. Read the **TRADE PLAN** card: direction, entry, stop, target, R:R.
3. Check **evidence_status** + **target_hit_rate** (the per-trigger table in
   the Calibration Health panel).  Proven → size normally.  Learning →
   small.  Paper-only → don't.
4. Place the order with the entry/stop/target from the call, or let the
   **Execute** flow submit it.
5. Manage toward the horizon: the call is valid for
   `hold_horizon_minutes`.  Stop hit = thesis wrong, out.  Target hit =
   objective reached, out (or trail the extended target only if the
   momentum evidence still supports it).
6. **Rate the outcome** (👍/👎 on the dashboard, or automatically via the
   auto-scorer task) — every outcome is scored and feeds the next
   calibration.  The system only gets more honest, not more optimistic.

## 6. Honest limits (read this before risking money)

- **Direction is ~50/50.**  The model does not know whether R_75 will go up
  or down over the next 6 hours — no model can, on a CSPRNG price feed.
  Treat the direction as a coin flip and the **R:R geometry + volatility
  timing as the only real edge**.
- **The volatility edge is real but small.**  The calibrated EGARCH bands
  (p50/p90) are honest: on R_75/R_100 they currently cover ~49–55% of p50
  outcomes and ~88–92% of p90 outcomes — close to the ideal 50%/90%.
  "Calibrated" means the *bands* are honest, NOT that the calls win.
- **Trade counts are still small.**  The empirical gate needs ≥10 scored
  outcomes per trigger type; today most types are still `still_learning`.
  Expect the dashboard to say PAPER ONLY until the auto-scorer task has
  compounded enough outcomes (a few days of running).
- **Never trade money you cannot afford to lose.**  This system is a
  research/automation platform, not a guarantee.

## 7. Key commands

```bash
# Generate one live call for R_75 (prints the full plan)
python -m synthetic_trader.cli live-snapshot --symbol R_75

# Watch continuously (emits calls to the journal + dashboard)
python -m synthetic_trader.cli live-watch --symbol R_75

# Score resolved calls into the outcomes journal (also runs daily via task)
python -m synthetic_trader.cli score-live-loop --once

# See how calibrated the vol bands are
python -m synthetic_trader.cli tick-coverage --json

# Check the collector/scorer tasks are healthy (exit 1 = warning)
python -m synthetic_trader.cli tick-task-health
```
